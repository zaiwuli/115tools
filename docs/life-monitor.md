# 生活事件增量发现

首次无成功检查点时只请求当天最新一页（1000条），不按开启时间排除该页旧记录，不向前回查。已有部署沿用检查点。

后续从当天向前读取至旧事件ID边界或上次检查日期；同一轮最多10页，页间3秒，页面重叠100条并按事件ID去重。偏移分页不能提供强一致快照；同时大量插入、删除时不能绝对保证无遗漏。

先本地合并同文件最新事件，跳过浏览/删除及明确非压缩包文件名，再校验候选父目录路径。同父目录本轮只查一次，匹配启用来源根目录或其子目录后只扫描变化目录当前层，不递归。没有文件名的记录保守查目录；不支持只移动整个文件夹而没有内部文件事件的完整发现。

必要事件缓存在Settings的life-monitor-pending，完成可靠扫描任务登记后推进life-monitor-state并清理。每轮目录校验最多70个，保留100次任务请求预算；页数或目录批次达到上限显示LIFE_BACKLOG并保存进度，下一周期继续。认证/限流等异常不改变旧成功边界。若扫描任务已有预算耗尽标记，仍需手动恢复，不能据检查完成认定已解压成功。

新增监测来源使用之后事件；已完成检查点之前的历史事件不会自动重放。默认正常周期30分钟，手动检查可立即启动一轮。

## 离线下载完成补充发现

同一轮监测复用统一离线任务快照，与本工具下载状态查询共享20秒缓存和并发锁；缓存过期才读取离线任务列表，每页100条、最多3页，页间隔3秒，共享监测任务100次请求预算。列表不保证按提交时间排序，因此不遇到旧任务就提前结束；超过3页的任务不保证覆盖，不递归或无限翻页。

仅接受明确成功状态（status=2），按任务哈希、提交时间和目标目录去重。首次仅将所读取页面内已有成功任务建立为基线，不扫描历史成功任务；正在下载的任务后续成功时仍可发现。后续只处理未核对成功任务，排除哈希匹配本工具本地Offline记录的任务（这些继续走原下载状态确认和补扫流程）。去重记录仅保存标识和核对时间，最多保留10000条，超出后旧任务可能重新核对。

根据wp_path_id校验下载目标目录归属，复用启用的115监测来源、离线目录和规则匹配；排除输出、归档、失败目录。只登记目标目录当前层的一次扫描，不递归，也不根据任务file_id假定它就是压缩包。目录核对与生活事件共享每轮70个上限，同目录只核对一次。成功登记扫描后保存去重状态；接口异常不确认任务。日志记录读取页数、成功任务候选及匹配扫描数量，不输出下载链接。

离线状态查询同样最多读取3页。缺失任务保持未确认，不根据列表缺失判定失败。仅status=2表示成功，失败但进度100%不再误判。

## 外部任务观察与待核对

匹配启用监测来源的未完成离线任务登记到离线记录，类型external，不重新提交下载。观察复用离线轮询与共享快照；明确成功后扫描目标目录当前层。明确失败停止观察，不允许使用重试提交入口。首次已成功任务建立基线，不回放。

已登记任务在不完整的3页快照中未找到，进入“待核对”；达到24小时也停止自动轮询。手动重新核对仍遵守3页上限。满24小时对目标目录当前层最多补查一次，仅唯一同名压缩包允许自动尝试解压，不把离线状态改成成功；找不到、同名不唯一、种子目录无法对应时保持待核对。超时目录补查每轮最多20个，无递归。已知仍下载中的同名文件不由普通扫描提前解压。
