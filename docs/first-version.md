# 115tools 第一版运行与验证说明

日期：2026-11-04。开发版本，尚未完成生产迁移验收。

## 运行

Windows 安装官方 7-Zip 后，在仓库根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,p115]"
npm ci --prefix frontend
npm run build --prefix frontend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 5656
```

访问 http://127.0.0.1:5656 。默认禁用真实 115 适配器；连接账号需按原有使用说明配置。不要把旧项目运行数据直接放进开发环境。

可在不提交的 `.env` 中配置 `WORK115_EXTRACTOR_PATH`，默认会发现系统 7zz/7z 和 Windows 官方安装位置。项目仍使用 WORK115 环境变量及旧数据库名称，以避免无关配置迁移。

## 本版实现

- 默认解压引擎改为 7zip，复用受控逐文件输出；常见 ZIP/TAR 暂保留原生 Python 解码路径。
- 保留密码候选、分卷、文件清单、磁盘余量、路径限制、摘要及任务后处理。
- Python 增加嵌套解压累计预算、深度限制、长名称映射和提层。
- 7-Zip 列表阶段拒绝大小写重复条目和负大小；显式错误程序路径不静默回退。
- 系统状态和页面显示实际 7-Zip 版本、路径及 CUE 兼容组件状态。
- Docker 增加固定官方 Linux 26.01 组件下载及 SHA-256 验证；amd64/arm64 地址和项目观测摘要记录在组件清单中。
- 测试目录和 Go 测试不再被 Git 忽略。

## 已取消的功能

用户确认不需要 CUE/FLAC 音轨切分，已移除 CUE 自动识别、伴随文件处理、旧 helper 调用及 Go 构建阶段，同时删除 extractor 和 third_party/xtractr 源文件。普通压缩包内的 CUE、FLAC、MP3 仍作为普通文件解压，不进行音频切分。

## 更新与限制

本版提供版本识别和固定版本构建，已包含每日检查、手动检查、关闭检查和最近 30 条检查历史；不提供运行中自动下载切换。升级 7-Zip 需更新组件清单和安装脚本中的版本与摘要，测试后发布。摘要为项目下载计算值，不是官方签名。

普通压缩包可使用 7-Zip；本版仍保留 Python ZIP/TAR 解码，不能宣称所有格式都由 7-Zip 处理。嵌套路径按严格冲突拒绝策略处理，复杂嵌套格式及递归分卷仍需扩大样本验证。

验证环境为 Windows、Python 3.13、官方 7-Zip 26.01。测试使用假的 115 适配器，未执行真实账号写操作；生产镜像使用 Python 3.12。当前没有 Docker 工具链，Linux 镜像运行及大型固实 RAR 性能尚未验收；真实小型 RAR/RAR5、固实和分卷样本已通过，缺卷会报错，见 rar-validation-results.json。不能将固实 7z 测试代替 RAR 测试。

本版不再依赖 xtractr；旧 extract_engine=xtractr 配置需改为 7zip，旧 XTRACTR_PATH 配置不再使用。

## 收尾结果与回退

已联网核实官方更新检查能识别候选版本；当前上游页面返回 26.05，本项目 Windows 样本验证版本仍为 26.01，不自动宣称候选兼容。后台在调度器启用时每天检查，失败也记录检查时间，避免断网时频繁请求。p115 保持锁定依赖，更新随应用发布。

镜像部署使用不可变 sha 标签。升级前备份数据目录的 config（数据库及 master.key 必须配套），记录当前镜像和组件版本；新镜像验证失败时停止服务，恢复旧镜像，若数据库格式有变化则同时恢复配套备份。本次改造没有增加数据库迁移。不要并行启动两个实例写同一个数据库。

本机部署升级前保留旧应用目录、虚拟环境和配套 7-Zip；停止应用后切换目录和 EXTRACTOR_PATH。回退时恢复旧应用及旧组件路径再启动，不覆盖正在执行的程序。

本机未提供 Docker 引擎，WSL 无 Linux 发行版，因此没有执行容器构建和容器内回退。未配置真实账号，115 实际联调仍需在有账号的环境验证。以上为剩余环境验收项，不冒充已通过。

## Linux 组件检测修复

官方 Linux 包使用静态 7zzs 安装为 /usr/local/bin/7zz，构建最终镜像时以 UID 1000 执行版本检查。版本识别兼容 Linux 的 7-Zip (z) 横幅；可用性以实际执行结果为准。检测失败返回明确错误码，更新判断为未知而非无需更新。本机仍未执行 Docker 构建，结果以 Actions 为准。

## 在线组件更新（新增）

运行状态页提供更新 7-Zip、更新 p115、分别回滚、清理过期版本。先检查上游，再选择安装。安装目录为数据目录的 components（默认 Compose 中为 /config/components），需允许 UID 1000 写入并保持持久化。

7-Zip 在线安装目前针对 Linux amd64/arm64 容器，官方 HTTPS 下载包有 32MiB 上限，只提取静态程序和许可证，核对版本并执行创建、校验及解压冒烟测试。没有验证上游签名，计算的 SHA-256 用于版本追踪；冒烟验证不等于全部格式兼容认证。更新失败不切换，正在执行的 worker 使用启动时的旧路径。

p115 按上游精确提交安装到独立 site 目录，不覆盖运行环境，执行导入验证；不执行真实账号写测试。当前容器进程仍使用旧版，等待任务结束后手动重启容器，新的 app.runtime.launch 入口加载选定版本。旧镜像没有此入口，需先升级至包含本功能的新镜像。主程序本身仍由镜像升级。

回滚当前选择与上一选择；首次在线更新可回到镜像内置组件。p115 回滚后同样需重启。不能把组件回滚当数据库恢复。

清理保留当前及上一版，更早目录超过 7 天才清理；正在运行的 p115 和持有租约的解压 worker 受保护。失败安装尝试立即清理目录。页面可手动清理，后台每日更新检查时也执行过期清理。暂不提供强制删除上一版。

本机测试覆盖状态切换、回到镜像默认、清理保护及原功能回归。本机非 Linux 且无 Docker，在线 Linux 安装与真实 p115 依赖更新尚需容器环境验收。不能宣称已完成容器端到端验证。

## 云解压成功后再本地解压

打开任务详情，点击“下载原包到本地解压”并确认。仅对有下载标识、云端成功且没有本地输出的 115 任务提供。创建独立本地任务，保留原云端成功记录；新任务保留原包，不重复云端归档或删除。同一原任务有活动的本地子任务时禁止重复创建。

原包按任务当前保存的定位和新获取的直链下载；不存在、权限失效或分卷缺失会在独立本地任务中失败，不会修改父任务。此版不在确认前遍历远端验证全部分卷。已归档文件使用保存的当前定位，若文件被外部移动且定位失效，不自动全盘搜索。

输出使用独立名称，在新任务详情查看实际路径；本地重试与取消使用已有任务操作。父任务详情列出最近本地执行状态。真实账号下载仍需目标环境验证。

## 离线成功后的文件发现

早期扫描与下载成功后的扫描共用目录任务键，成功且已关联的单文件不再安排扫描。尚未关联的成功项最多执行两轮完整目录扫描，第二轮间隔 120 秒；分页/子目录续扫属于同一轮。扫描开始早于成功观测的不计入这两轮；已有活动扫描不另建并行任务。两轮未发现则进入“文件发现待核对”，可在离线记录操作栏点击“重新扫描产物”，手动增加一轮，不重新提交下载。多文件完整性仍按现有匹配和待核对逻辑处理，不承诺自动证明目录全部产物完整。

升级后会对下载成功且未关联、仍停在 discover 的旧项启动此流程，关联后按当前规则自动执行解压；不重新下载。

## 外部日志与页面日志

离线提交、开始下载、下载成功和下载失败会同时写入容器标准输出与工作日志事件。标准输出采用 `YYYY-MM-DD HH:MM:SS.mmm | 级别` 两行格式，包含中文说明和状态图标；UI 的工作日志保留任务编号、阶段和详细信息。两处日志内容均不包含令牌、Cookie 或密码。


### 手动重试云解压与控制台日志

115 压缩包未云解压成功时，列表和详情提供小型重试图标。等待密码、云端超时以及已结束的本地处理均可重新发起；正在执行、结果待核对和原包位置待核对时禁止重复提交。手动重试保留密码及规则，开启新的执行记录并重置本轮次数、计时。云端成功独立记录，避免本地成功误判。

控制台过滤成功 HTTP 请求（包括 UI 轮询和健康检查），保留 4xx/5xx 并统一时间与级别格式；访问日志不输出查询参数。服务异常保留堆栈，业务事件继续通过工作日志查询。
