# 网盘查询优化（本地草稿）

## 已实现

- 调度任务中的 P115Adapter.call 在发出请求前扣除持久预算，重启和失败重入不清零。
- 云解压每轮最多 60 次接口请求，同时保持既有总超时（默认 900 秒）、密码库有限尝试和内容失败最多 3 轮。
- 目录扫描每个周期最多 200 次、动态监控每轮最多 100 次、离线状态每轮最多 100 次；其余调度调用默认 200 次。
- 超预算停止自动调度，不会被周期 enqueue 重置；明确的人工操作可开启新预算。限额统计分页、目录创建和变更等 call 请求，并非仅进度查询。
- 离线状态保留 24 小时截止、离线成功后的产物发现保留最多两轮；不增加成功后检查；超时后核对为独立可选功能，默认关闭。
- 扫描、动态监控、离线查询和提交连续异常最多 3 次，间隔至少 300 秒；扫描积压超范围直接停止。
- 认证/挑战异常停止云解压，等待人工处理；记录失败分类和远端错误码。限流沿用全局持久熔断退避。
- 详情展示本轮请求次数、上限、云处理累计耗时；沿用步骤记录，不为显示进度增加请求。

## 边界与后续

这些是调度任务预算，不是全局终身请求上限。长期监控在成功结束后下一轮重新计数，失败预算耗尽后不会自动重开。直接管理接口、适配器 download_url 等非 call 路径不由该预算计数，需单独审计；不能声称所有网盘流量已有统一限制。当前没有接入上游百分比，避免推测进度。未确定输出目录隔离存在故障，本轮未改变其行为。

认证恢复与长期监控预算耗尽后的专用恢复入口仍需完善，当前以明确提示和手动操作为主。本轮固定上限为保守初版，需要在实际目录规模下验证，超限不应盲目提高。


## 可选超时核对

系统设置 → 调度节奏 → 超时后核对。默认关闭，仅对开启之后新超时且具有远端操作 ID 的任务安排。默认首次延迟900秒、间隔1800秒、最多2次；允许1–3次，延迟和间隔至少900秒。次数在请求前持久化，异常和重启也不恢复次数。不提交新的云解压，不扫描输出目录；明确成功后执行原有成功和后处理流程，明确失败、认证/限流/熔断或次数用尽则停止。任务详情支持立即核对（消耗原预算）和停止。切换本地、重试、取消、关闭功能后不会继续旧核对。
